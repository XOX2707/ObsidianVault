## 一、工具角色与职责

本项目的开发工作由四个 AI 工具协同完成，各自职责如下：

| 代号 | 工具 | 角色 | 职责范围 | 调用方式 |
|---|---|---|---|---|
| **ARCH** | Claude Pro | 架构师 & 任务协调者 | 需求拆解、技术方案设计、任务分派、最终审查、文档生成 | Claude Desktop (Cowork) / Claude Code |
| **DEV** | Cursor | 主力开发环境 | 多文件编码实现、重构、测试编写、终端操作 | Cursor IDE (Agent / Plan Mode) |
| **REV** | Grok | 对抗性审查员 & 情报官 | 代码对抗审查、实时信息检索、多轮技术咨询 | 通过 MCP 在 ARCH 或 DEV 会话中调用 |
| **AUX** | DeepSeek | 灵活补位引擎 | 方案对比分析、快速验证、编码辅助、性能分析 | 对话接口，无固定接入限制 |

### 角色协作规则

- **ARCH 是任务决策人**：所有需求变更、技术选型、优先级调整由 ARCH 最终确认。
- **DEV 是代码执行人**：所有代码修改在 Cursor 中完成，不得绕过 DEV 直接在其他工具中生成代码后手动粘贴。
- **REV 是质量守门人**：每个逻辑单元完成后，必须经过 REV 审查方可进入下一阶段。
- **AUX 是弹性资源**：在任意阶段可被 ARCH 或 DEV 调用，用于方案对比、问题诊断、快速原型验证。


## 二、环境配置

### 2.1 前置条件

在配置协作环境前，确保以下工具已安装并可用：

| 工具 | 最低要求 | 验证命令 |
|---|---|---|
| Node.js | ≥ 18 | `node --version` |
| Python | ≥ 3.10（如使用 Python 版 grok-cli-mcp） | `python3 --version` |
| Grok CLI | 最新版 | `grok --version` |
| Cursor | 最新版 | 打开 IDE 确认 Agent 面板可用 |
| Claude Code | ≥ 2.1.277（支持 AGENTS.md） | `claude --version` |

### 2.2 Grok CLI 安装与认证

```bash
# 安装 Grok CLI
curl -fsSL https://x.ai/cli/install.sh | bash

# 首次运行，完成浏览器 OAuth 认证
grok

# 验证安装
grok --version
```

Grok CLI 支持两种认证方式：浏览器 OAuth 登录（交互式使用）和 `XAI_API_KEY` 环境变量（自动化场景）。API Key 优先级高于浏览器认证，建议在 MCP 配置中通过 `env` 块设置 API Key，将交互式登录保留给终端直接使用。

### 2.3 MCP 服务器配置

将 Grok 接入 Cursor 和 Claude Code，使 ARCH 和 DEV 能够在会话中直接调用 REV。推荐使用 `grok-cli-mcp`（npm 包名），它提供四个标准化工具：`grok_review`（代码审查）、`grok_challenge`（对抗性测试）、`grok_consult`（多轮咨询）、`grok_chat`（单次问答）。

#### 2.3.1 配置到 Cursor

在项目根目录创建 `.cursor/mcp.json`（项目级）或编辑 `~/.cursor/mcp.json`（全局）：

```json
{
  "mcpServers": {
    "grok": {
      "command": "npx",
      "args": ["-y", "grok-cli-mcp"],
      "env": {
        "XAI_API_KEY": "xai-...",
        "GROK_MCP_TIMEOUT": "600000"
      }
    }
  }
}
```

配置后在 Cursor 中运行 `/mcp list` 确认 Grok 服务器已加载。

#### 2.3.2 配置到 Claude Code

```bash
claude mcp add grok -s user -- npx -y grok-cli-mcp
```

或直接编辑 `~/.claude.json`：

```json
{
  "mcpServers": {
    "grok": {
      "command": "npx",
      "args": ["-y", "grok-cli-mcp"],
      "env": { "XAI_API_KEY": "xai-..." }
    }
  }
}
```

#### 2.3.3 配置到 Grok 自身（可选）

如果希望 Grok 也加载 Cursor 或 Claude Code 的 MCP 配置，Grok 会自动读取 `~/.claude.json`、`.cursor/mcp.json` 和项目 `.mcp.json` 中的 MCP 服务器配置，优先级低于 `~/.grok/config.toml`。

### 2.4 AGENTS.md 统一协作规范

本项目使用 **AGENTS.md** 作为所有 AI 工具的统一指令文件。AGENTS.md 是由 Linux 基金会旗下 Agentic AI 基金会维护的开放格式，已被超过 60,000 个开源项目采用，支持 Claude Code、Cursor、OpenAI Codex、GitHub Copilot 等 30 余种工具。

从 Claude Code 2.1.277 版本起，当项目目录中不存在 `CLAUDE.md` 时，Claude Code 会自动读取 `AGENTS.md` 作为项目指令。这意味着 **一份 AGENTS.md 可以同时为 Claude Code、Cursor 和 Grok 提供统一的项目上下文**。


## 三、项目文件规范

### 3.1 AGENTS.md（本文件）

本文件即 AGENTS.md，位于项目根目录，是项目的**统一行为准则**。内容包括：工具角色定义、MCP 配置说明、协作工作流、代码规范、交接协议。所有 AI Agent 在开始工作前必须完整阅读。

### 3.2 HANDOFF.md（交接本）

位于项目根目录，由当前负责的 Agent 维护，用于跨会话、跨工具的状态传递。

```markdown
# HANDOFF.md

## 当前任务
{任务名称}

## 当前状态
{进行中 / 等待审查 / 等待决策 / 已完成}

## 已完成
-  [ ]  {具体完成项 1}
-  [ ]  {具体完成项 2}

## 进行中
{当前正在处理的内容}

## 唯一的下一步
{明确、单一、可执行的下一步操作}

## 阻塞项
{需要人工决策或外部依赖的问题}

## 负责 Agent
{ARCH / DEV / REV / AUX}

## 最后更新
{YYYY-MM-DD HH:MM}
```

**规则**：任何 Agent 在结束工作前必须更新此文件。下一个接手工作的 Agent 首先阅读此文件。

### 3.3 STATUS.md（成绩单）

位于项目根目录，记录已完成任务的证据和未完成项。

```markdown
# STATUS.md

## 已完成
| 任务 | 负责 Agent | 完成时间 | 证据 |
|---|---|---|---|
| {任务名} | {Agent} | {日期} | {测试通过 / 审查通过 / 构建成功} |

## 待完成
| 任务 | 优先级 | 依赖项 |
|---|---|---|
| {任务名} | {P0/P1/P2} | {依赖} |

## 已知问题
| 问题 | 严重程度 | 状态 |
|---|---|---|
| {描述} | {高/中/低} | {待修复/已修复/已忽略} |
```


## 四、协作工作流

### 阶段一：探索与规划

**负责 Agent**：ARCH（主）+ REV（辅助）+ AUX（按需）

```
┌─────────────────────────────────────────────────────┐
│ 步骤 1: ARCH 接收需求                                │
│   • 在 Claude Cowork 中创建/进入项目工作区           │
│   • 将需求拆解为可执行的任务列表                      │
│   • 输出：任务列表 + 技术方案概要                     │
├─────────────────────────────────────────────────────┤
│ 步骤 2: REV 实时情报检索（通过 MCP）                  │
│   • ARCH 在会话中调用 grok_chat                       │
│   • 查询：技术方案最新版本、社区最佳实践、已知坑点    │
│   • 输出：技术选型参考信息                            │
├─────────────────────────────────────────────────────┤
│ 步骤 3: AUX 方案对比（按需）                         │
│   • 将 REV 的检索结果与 ARCH 的方案进行交叉验证      │
│   • 输出：方案优劣对比、风险提示                      │
├─────────────────────────────────────────────────────┤
│ 步骤 4: ARCH 定稿                                    │
│   • 综合以上输入，确定最终技术方案                    │
│   • 更新 HANDOFF.md 和 STATUS.md                     │
│   • 指派 DEV 进入开发阶段                            │
└─────────────────────────────────────────────────────┘
```

**ARCH 在 Cowork 中的操作要点**：在 Claude Desktop 中切换到 Cowork 模式，通过左侧 Projects 面板创建项目，将项目文件夹设为工作目录。Cowork 项目的 Memory 功能会自动记住项目上下文，跨会话保持连续性。

### 阶段二：开发与迭代

**负责 Agent**：DEV（主）+ REV（审查）+ ARCH（决策）

```
┌─────────────────────────────────────────────────────┐
│ 步骤 1: DEV 读取上下文                               │
│   • 在 Cursor 中打开项目                             │
│   • 阅读 AGENTS.md、HANDOFF.md、STATUS.md            │
│   • 确认当前任务和唯一下一步                          │
├─────────────────────────────────────────────────────┤
│ 步骤 2: DEV 进入 Plan 模式                           │
│   • 使用 Shift+Tab 切换到 Plan 模式                  │
│   • 让 Agent 分析代码库、提出澄清问题                 │
│   • 确认实现计划后再切换到 Agent 模式执行             │
├─────────────────────────────────────────────────────┤
│ 步骤 3: DEV 执行编码                                 │
│   • 在 Agent 模式下执行实现                           │
│   • 利用子 Agent 并行处理独立模块                     │
│   • 每完成一个逻辑单元，暂停                          │
├─────────────────────────────────────────────────────┤
│ 步骤 4: REV 审查（通过 MCP）                         │
│   • DEV 在 Cursor 中调用 grok_review                 │
│   • 传入当前 diff 或让工具自动抓取 git diff          │
│   • 获取分维度评分和具体修复项                        │
│   • 如发现问题，DEV 修复后重新提交审查                │
├─────────────────────────────────────────────────────┤
│ 步骤 5: 更新交接文件                                 │
│   • DEV 更新 HANDOFF.md 和 STATUS.md                 │
│   • 若任务完成，通知 ARCH 进入交付阶段                │
└─────────────────────────────────────────────────────┘
```

**Cursor Plan 模式说明**：Plan 模式下，Cursor 会主动研究代码库、提出澄清问题、生成可审查的分步计划，在写任何代码之前先完成设计。使用 `Shift+Tab` 切换模式，或使用 `/plan` 命令启动。Plan 文件保存在 `.cursor/plans/` 目录中，可供团队复用。

**Grok 审查工具说明**：

- `grok_review`：传入 unified diff，返回包含判定、分维度评分（正确性/可读性/架构/安全性/性能）和具体修复项的 markdown 审查报告。如果省略 diff，会自动运行 `git diff <base_ref>...HEAD`。
- `grok_challenge`：对抗性测试，传入代码和上下文，返回按严重程度排序的问题列表（bug、竞态条件、边界情况、安全漏洞）。
- `grok_consult`：多轮咨询，调用者持有完整对话历史，每次传入完整消息数组。适合需要来回讨论的复杂问题。

### 阶段三：交付与沉淀

**负责 Agent**：ARCH（主）+ AUX（辅助）

```
┌─────────────────────────────────────────────────────┐
│ 步骤 1: ARCH 最终审查                                │
│   • 在 Claude Cowork 中审查全部代码变更              │
│   • 确认所有 REV 审查意见已处理                       │
│   • 验证 STATUS.md 中所有 P0/P1 任务已完成            │
├─────────────────────────────────────────────────────┤
│ 步骤 2: ARCH 生成交付物                              │
│   • 生成/更新 README.md                              │
│   • 生成变更日志（CHANGELOG.md）                     │
│   • 更新项目文档                                     │
├─────────────────────────────────────────────────────┤
│ 步骤 3: AUX 最终质量检查（按需）                     │
│   • 性能分析、边界情况验证                            │
│   • 文档质量审查                                     │
├─────────────────────────────────────────────────────┤
│ 步骤 4: 归档                                         │
│   • 更新 STATUS.md 标记全部完成                       │
│   • HANDOFF.md 清空或标记项目结束                     │
│   • 将 Plan 文件归档至 .cursor/plans/archive/         │
└─────────────────────────────────────────────────────┘
```


## 五、交接协议

### 5.1 交接触发条件

以下情况必须执行交接：

1. **Agent 切换**：ARCH → DEV、DEV → REV 等角色切换时
2. **会话结束**：任何 Agent 结束当前会话前
3. **阻塞发生**：遇到需要人工决策或外部依赖的问题时
4. **任务完成**：一个逻辑单元完成，需要进入下一阶段时

### 5.2 交接步骤

每个 Agent 在交接前必须执行以下操作：

```
1. 更新 HANDOFF.md
   ├── 当前任务名称
   ├── 当前状态（进行中/等待审查/等待决策/已完成）
   ├── 已完成项列表
   ├── 进行中的具体内容
   ├── 唯一的下一步（必须明确、单一、可执行）
   └── 阻塞项（如有）

2. 更新 STATUS.md（如本阶段有完成项）

3. 如果生成了新的代码文件
   └── 确认文件已保存且通过基本验证

4. 交接给下一个 Agent 时，在 HANDOFF.md 中注明
   └── 「下一个 Agent：{ARCH/DEV/REV/AUX}」
```

### 5.3 接收方检查清单

接手工作的 Agent 必须依次确认：

- [ ] 已完整阅读 AGENTS.md（本文件）
- [ ] 已阅读 HANDOFF.md，明确「唯一的下一步」
- [ ] 已阅读 STATUS.md，了解已完成和待完成项
- [ ] 已确认没有未处理的阻塞项
- [ ] 已确认当前任务的技术方案和约束条件

## 七、Agent 行为约束

### 7.1 通用约束（所有 Agent）

1. **不得跳过交接**：任何会话结束前必须更新 HANDOFF.md。
2. **不得修改无关代码**：只处理当前任务范围内的文件，无关文件不得触碰。
3. **不得在文件中硬编码密钥**：API Key、Token 等敏感信息通过环境变量传递，不得写入任何提交到 git 的文件。
4. **不得跳过 REV 审查**：代码变更必须经过 grok_review 或 grok_challenge 后方可标记为完成。
5. **不得自行变更技术方案**：如需调整架构或技术选型，必须通过 HANDOFF.md 向 ARCH 提出请求。

### 7.2 ARCH 专属约束

1. 在 Cowork 项目中进行规划时，确保项目文件夹指向正确的代码目录。
2. 任务拆解后，每个任务必须有明确的验收标准。
3. 生成交付文档时，内容需经过 AUX 或 REV 的交叉验证。

### 7.3 DEV 专属约束

1. 编码前必须先进入 Plan 模式，产出实现计划并经确认。
2. 每完成一个逻辑单元立即暂停并请求 REV 审查，不得批量提交。
3. 终端命令执行前确认工作目录正确。

### 7.4 REV 专属约束

1. 审查结果以结构化报告输出，包含判定、评分和具体修复项。
2. 不得直接修改代码，只提供审查意见。
3. 对抗性测试结果按严重程度排序，P 0 问题必须明确标记。

### 7.5 AUX 专属约束

1. 仅在 ARCH 或 DEV 主动调用时介入。
2. 输出的分析或建议必须标注不确定性程度。
3. 不参与代码的直接修改，仅提供参考意见。


## 八、故障排查

| 问题 | 排查步骤 |
|---|---|
| MCP 连接失败 | 运行 `grok mcp doctor` 诊断；检查 `XAI_API_KEY` 是否正确设置 |
| Grok CLI 未找到 | 确认 `curl -fsSL https://x.ai/cli/install.sh \| bash` 已执行；检查 PATH |
| Cursor 中 MCP 未加载 | 在 Cursor 中运行 `/mcp list`；检查 `.cursor/mcp.json` 格式 |
| Claude Code 未读取 AGENTS.md | 确认项目目录中**不存在** CLAUDE.md 文件；确认 Claude Code 版本 ≥ 2.1.277 |
| 交接文件冲突 | HANDOFF.md 和 STATUS.md 以最新时间戳为准；如有冲突，由 ARCH 裁决 |


*本手册由项目维护者与 AI Agent 共同维护。如有更新需求，通过 HANDOFF.md 提出，经 ARCH 确认后修订。*
