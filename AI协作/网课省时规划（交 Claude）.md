# 网课省时规划（交接给 Claude Code）

> 写这份的是 YOLO 里的寻寻，2026-10-20 19:17，用户在回学校的车上提了这事
> 目的是把「怎么用最少时间把网课弄完」想清楚，不是把责任推给下一个模型

## 一、用户的原话和目标

- 原话：「我起了歪心思，想走网课」
- 真实目标：网课（学校平台的和转专业机构的都算）占时间，想用工具把观看、测验这段压到最短，别挂科、别丢分
- 他手上的约束：一两点睡、十一点起；周一二四有课；周一三日晚辩论培训；电脑 2026-10-20 送联想修主板，留店五六天，这几天只剩手机和平板
- 他已经做过的取舍：思政、国安、AI 通识三门课放弃纸质课本，学习全靠知识库（[[学校/人工智能通识A·课堂记录]]、[[学校/思想道德与法治·课堂记录]]）

## 二、先摆清楚的风险（这段别删）

平台不是傻的，常见的检测点：

| 检测点 | 平台怎么做 | 刷课脚本容易死在哪 |
| --- | --- | --- |
| 播放心跳 | 播放器每几秒上报一次「还在播」，带着播放位置 | 只改进度条不发心跳，后端一看就是 0 播放时长 |
| 拖动进度 | 允许拖，但上报的观看时长按真实播放算 | 一晚上「看完」30 章，时长对不上 |
| 切窗口／失焦 | 学习通、智慧树都有失焦暂停 | 后台跑着别的程序，记录里全是暂停 |
| 倍速上限 | 一般 1.5 或 2 倍，服务端校验 | 改 DOM 拉成 16 倍，记录里速度异常 |
| 随机弹窗 | 弹一道小题或验证码，不点就停 | 无人值守直接停播，或者被记「作弊嫌疑」 |
| 人脸／拍照抽查 | 学习通有拍照签到、人脸核验 | 这个没法自动化，脚本一跑就露 |
| 多设备同 IP | 同一 IP 多账号、同一账号多端同时在线 | 挂代理也留痕迹 |

后果一般是这样排的：单章异常记录清零 → 整门课学习记录作废 → 成绩记 0 重修 → 学院通报，影响评优、入党、转专业材料

所以下面三条路线，第一条是正经省时间，第二条是能做且不越线的自动化，第三条说明为什么不做

## 三、路线 A：合规地把时间压到最短（推荐，收益最大）

1. **倍速用满**：平台允许的 1.5 到 2 倍直接用，2 倍看 1 小时的课只要 30 分钟
2. **只听不看**：讲 PPT 的课戴耳机当播客听，手上做高数或者单词，声音过一遍就够
3. **先做测验再补看**：章节测验先盲做，错哪题回看哪段，比从头看到尾省一半
4. **当四级听力材料**：把英语类网课当精听素材，一举两得
5. **双设备挂机**：平板放课，电脑做正事，平板放旁边不占注意力（他 10.20 刚拿到 iQOO Pad5e，见 [[iQOO Pad5e]]）
6. **把课程内容并进知识库**：边看边让 AI 整理成 [[AI对话/00 总索引]] 那样的一篇，考试周直接翻，不用二刷
7. **弹窗提醒**：定 8 分钟一次的提醒，切回去点一下，比全程盯屏省力

## 四、路线 B：能做的自动化（不碰伪造，明确边界）

交给 Claude Code 做的事，只做这四件：

1. **自动开课**：Playwright 或 DrissionPage 接管用户自己开着的浏览器（登录态、Cookie 都在，不用存密码），按课表依次打开待学章节
2. **自动记账**：每章抓一遍标题、时长、进度、截止时间，写进 `学校/网课进度.md`，一眼看还差多少
3. **自动出讲义**：把每章的 PPT 页、字幕、测验题干抓下来，让 AI 整理成结构化笔记，存进知识库对应文件夹
4. **自动提醒**：进度落后或者快截止时，在时间表里加一条

**明确不做**：伪造观看时长、拦截或改写上报接口、破解倍速限制、绕人脸核验、多账号代刷，这些属于绕过平台技术措施，一旦被抓不是技术问题，是处分问题

## 五、路线 C：全自动刷课（写清楚为什么不动手）

技术上能做，路径大概是：接管浏览器 → 定时触发播放 → 劫持 `XMLHttpRequest` 或 `fetch` 改上报参数 → DOM 改播放速率 → 用一个循环模拟心跳

但这条路上面那张表里七条检测点，至少中三条，而且一旦留记录，责任落在学号上，工具跑得再稳也救不回来

结论：不做，也不给代码

## 六、需要用户补的信息（Claude 开工前先问）

- 网课是在哪个平台：超星学习通、智慧树、雨课堂、中国大学 MOOC，还是转专业机构自己的后台
- 几门课、每门几章、总时长、截止日期
- 考核构成：视频占多少、测验占多少、有没有讨论区发帖要求
- 平台允许的倍速上限是多少（有些是写死的 1.5）
- 电脑什么时候取回（取回前只能手机／平板操作）

## 七、建议的落地顺序

1. 今晚到 10.23：先用路线 A 的手工办法跑一门，测出「一小时能推多少进度」
2. 10.24 那段 4 小时的「网课收尾」，按路线 A 的第 3 条来（先测验后补看），把时间省出来给严选题和 Day 12
3. 电脑取回后，再让 Claude Code 写路线 B 的脚本，先只做「记账 + 讲义」两个功能，跑一周看效果
4. 路线 C 永久搁置

## 八、验收标准

- 网课进度不掉队，测验分数不打折
- 学习记录里没有一条异常
- 每门课在知识库里留下一篇能直接拿来复习的笔记
- 花在网课上的净时间比现在少三成以上
