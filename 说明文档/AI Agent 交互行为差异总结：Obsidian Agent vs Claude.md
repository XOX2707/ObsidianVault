
> **背景**：用户向两个 AI Agent 发送了同一句包含歧义的指令：“deepseek-v 4-pro 你来负责总结，claude-opus-5-5 你来负责技术支持”。两个模型给出了截然不同的响应策略。

## 🔍 现象对比

| 模型 | 响应策略 | 核心表现 |
| :--- | :--- | :--- |
| **Obsidian Agent**<br>(deepseek-v 4-pro) | **中断询问，抛回决策权** | 识别到“你”指代不明，停止执行，弹出结构化表单，要求用户明确指定每个“你”分别指代谁。 |
| **Claude**<br>(claude-opus-5-5) | **合理假设，带草案确认** | 同样识别到歧义，但结合上下文（文件名“本地助手 vs Obsidian Agent”）推断出合理分工，直接给出草案并附带执行提示（给出 diff）。 |

## 💡 核心差异原因分析

### 1. 风险偏好与系统提示词（System Prompt）
- **Obsidian Agent**：处于本地严谨文档环境，系统提示词大概率强调“绝不擅自揣测，遇不确定必须提问”。因此触发安全防御机制，通过 UI 组件强制澄清。
- **Claude**：被训练得极具“行动力（Bias for action）”和“高情商”。倾向于把“填空题”变为“判断题”，先给默认解，让用户确认。

### 2. 上下文推理倾向（Context Awareness）
- **Obsidian Agent**：纠结于 **Syntax（语法）**。“你说的‘你’到底是谁？主语不明，不能动手。”
- **Claude**：依赖于 **Semantics（语义）**。“根据标题，我是 Obsidian Agent，那我就负责总结；本地助手负责技术。”还会主动询问“还有什么要一起定的吗？”

### 3. UI 交互范式（Affordance）
- **Obsidian Agent**：UI 包含“模型向你发起提问”的交互组件（勾选框、输入框）。这种设计天然引导 Agent 将不确定项转化为表单向用户提问，并强调“契约式确认”。
- **Claude**：纯自然语言对话框，缺乏表单组件，只能通过长文本表达思考，直接给出默认执行方案。

### 4. 模型性格差异
- **Obsidian Agent (DeepSeek)**：像**极其严谨的法务/技术文档审核员**——“你不说清楚，我绝不签字。”
- **Claude**：像**资深的技术执行助理**——“我猜到了你的大概意思，方案我拟好了，你点个头就行。”

## 🛠️ 用户调教建议

根据需求，可以通过修改提示词来引导 Agent 的行为：

**如果你更喜欢 Claude 的模式（带假设直接推进）：**
> 在 Obsidian Agent 的提示词中加上：
> *“如果遇到指令歧义，请结合上下文给出你认为最合理的默认假设，并直接给出执行草案，不要停下来问我。”*

**如果你更喜欢 Obsidian Agent 的严谨（但觉得烦）：**
> 在指令中避免使用代词，消除歧义：
> *“我来负责总揽，deepseek-v 4-pro 负责总结，claude-opus-5-5 负责技术支持，并把此分工写进文档。”*

## 📝 总结

- **Obsidian Agent 的“死板”**：在维护复杂本地知识库时是优点，能防止 AI 幻觉污染文档，适合严谨的归档与契约确认。
- **Claude 的“圆滑”**：在头脑风暴、快速推进和探索性任务时更爽，适合需要高效产出的场景。
