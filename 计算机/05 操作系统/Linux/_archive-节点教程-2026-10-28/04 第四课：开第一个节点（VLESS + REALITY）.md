# 04 第四课：开第一个节点（VLESS + REALITY）

回到 [[计算机/操作系统/Linux/README|学习地图]] · 前置：[[03 第三课：装 3x-ui 面板]]

## 目标

在 3x-ui 中创建 **VLESS + REALITY + RAW + Flow `xtls-rprx-vision`** 入站，导入 Clash Verge Rev，使出口 IP 显示为美国。

## 验收标准

- [ ] 入站备注为 `US-9929`（或你自定且能识别）
- [ ] 协议栈：VLESS / REALITY / RAW / Flow=`xtls-rprx-vision`
- [ ] 入站端口已在**安全组放行**；优先 **443**；若机房过滤 443 入站则改用高端口（本实验实通 **`39521`**），且**面板、安全组、客户端三处一致**
- [ ] Clash 能选中该节点；`curl` 经混合端口访问 `ipinfo.io` 得 `"country": "US"`（或等价美国出口）
- [ ] 笔记中无 UUID、REALITY 私钥、完整 `vless://` 链接明文

## 前置条件

- 面板可登录（3x-ui v3.11）
- 已理解：SSH=`62027`、面板=`35123`、入站端口**另选**
- Windows 已装 **Clash Verge Rev**；本机 mixed-port 以设置为准（本实验机为 **`12334`**，**不是**文档里常写的 7897）
- 安全组可随时加一条 TCP 入站

---

## 为什么选 VLESS + REALITY

| 组件 | 作用 |
| --- | --- |
| VLESS | 轻量；传输层之上的加密/伪装由 REALITY 等承担 |
| REALITY | 无需自有域名与证书；借用真实站点握手特征做伪装 |
| RAW | 即原 TCP（新版面板改名）；本方案不要 WebSocket/gRPC/XHTTP |
| Flow `xtls-rprx-vision` | 与 REALITY 常见推荐组合 |

不备案、不买域名证书即可起步；代价是依赖目标站可达与客户端内核能力。

---

## 步骤

左侧 **入站** → 右上 **添加入站**。

### 1. 基础配置

| 字段 | 填什么 |
| --- | --- |
| 备注 | `US-9929` |
| 协议 | **VLESS** |
| 监听 IP | 留空（监听所有） |
| 端口 | **优先 `443`**；若创建后外网不通而本机监听正常，怀疑机房过滤 443 时改用高端口（实机 **`39521`**） |
| 总流量 / 到期 | `0` / 留空（按需） |

**勿占用**：`62027`（SSH）、`35123`（面板）。

### 2. 协议（客户端）

| 字段 | 填什么 |
| --- | --- |
| 添加客户端 | 点一次生成一行 |
| 邮箱 / 备注 | 如 `me` |
| 流控（Flow） | **`xtls-rprx-vision`** |
| UUID | 面板生成；笔记写 `<uuid>`，勿贴全文 |

### 3. 传输

| 字段 | 填什么 |
| --- | --- |
| 传输 | **RAW**（旧称 TCP） |

### 4. 安全（REALITY）

| 字段 | 填什么 |
| --- | --- |
| 安全 | **reality** |
| 目标（Dest） | `www.microsoft.com:443` |
| SNI / serverNames | `www.microsoft.com` |
| 公钥 / 私钥 | 点 **获取新证书 / Get New Cert** 生成（**私钥不进笔记**） |
| ShortId | 点随机生成，不可空 |
| SpiderX | `/` |

> 创建前确认：密钥对与 ShortId 都有值。空 REALITY 段会导致 502 / 节点未写入。

### 5. 嗅探

开启 `http`、`tls`（便于识别域名；一般不影响连通）。

### 6. 高级

保持默认 → **创建**。

**预期**：入站列表出现 `US-9929`；Xray 仍为 Running。

服务器侧抽查（可选）：

```bash
grep -c '"protocol": "vless"' /usr/local/x-ui/bin/config.json 2>/dev/null || grep -ci vless /usr/local/x-ui/bin/config.json
```

**预期**：计数 ≥ 1 表示配置里已有 VLESS（路径以实机安装为准）。

安全组：为**实际入站端口**放行 TCP（443 或 39521）。

---

## 导入 Clash Verge Rev

1. 入站行 → **复制链接**（完整 `vless://…`，一次性用，勿存进公开笔记）。
2. Clash Verge Rev → 订阅/配置 → 从剪贴板导入或新建粘贴。
3. 在「代理」页选中该节点（若在某订阅的「代理增强」里，到对应分组找）。
4. 查看 **混合端口（mixed-port）**：
   - Rev 许多版本默认曾用 `7897`；
   - **本实验机实际为 `12334`** —— 以下 `curl` 必须与你的设置一致。

### 验收出口 IP

在本机 PowerShell 或已装 curl 的环境：

```powershell
curl.exe -x http://127.0.0.1:12334 https://ipinfo.io
```

**预期**：JSON 中 `"country": "US"`（或城市/ASN 对应该 VPS）。

若你确认 mixed-port 不是 12334，把命令里的端口改成设置页显示的值。

## 踩坑 / 回滚

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 创建端口被占 | 443 或其他进程占用 | `ss -tlnp`；换 `8443`/`39521` 等并同步安全组与客户端 |
| 客户端无网 | 安全组未放行入站端口 | 后台加规则 |
| REALITY handshake 失败 | Dest/SNI 不可达或填错 | 试 `www.cloudflare.com:443` 等同构目标 |
| 服务端正常、客户端仍握手失败 | Clash 内核未开后量子相关选项（如 `support-x25519mlkem768`，视 Xray 版本要求） | 在 Clash Verge 打开对应项后重启内核 |
| **443 外网不通、换高端口即通** | **机房过滤 443 入站**（非本机 firewall 误判） | 改用高端口（实机 **39521**）；教程「优先 443」与「实机端口」写清楚并保持三处一致 |
| 节点灰色 / 导入失败 | 链接截断 | 重新「复制链接」 |
| 很慢 | 跨洋 + 未开 BBR 等 | 先确认 [[02 第二课：开 BBR（网络提速）]] |
| 点创建 502、节点没写上 | 请求失败或 REALITY 密钥空 | `x-ui restart`；重建时先「获取新证书」且 ShortId 有值 |
| 重启后面板整页 502，服务器 `curl` 本地却 200 | **路径上的代理问题**：浏览器走了 Clash 系统代理 | 关系统代理；或加 **`IP-CIDR,192.220.37.75/32,DIRECT`**（勿用 SRC-IP-CIDR）；或换网络试 |
| curl 连错端口 | 以为默认 7897 | 以 Verge 设置为准；本机用 **12334** |

Clash 面板直连规则：

```yaml
- IP-CIDR,192.220.37.75/32,DIRECT
```

**回滚**：

1. 面板入站 → 删除该条 → 保存/重启 Xray。
2. Clash 中移除对应配置。
3. 安全组可删临时高端口规则（若不再使用）。

---

## 一句话记住

VLESS 管承载，REALITY 管伪装，RAW + vision 凑齐一条链；**端口以实机可通为准（443 优先，不通就高端口并三处同步）**；Clash 验收用本机真实 mixed-port（这里是 **12334**）。
